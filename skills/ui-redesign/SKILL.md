# UI redesign skill

You are restyling an existing, working trading-bot control panel. The page is live-trading software: a broken button can leave real positions open. Looks change; behaviour does not.

## Read these first, in order

1. `UI_REDESIGN_BRIEF.md`: what you may and may not touch, and the full preserve list.
2. `DESIGN_SYSTEM.md`: the tokens, type, and component rules to build to.
3. This file: how to work.

If anything in the brief and the design system conflict, the brief wins, because it protects behaviour.

## How the page is built (so you do not get surprised)

- One file, `static/index.html`, with Tailwind through the CDN (`darkMode: 'class'`), a big inline `<script>`, and `static/styles.css`.
- A lot of the UI is generated by JavaScript as HTML strings with Tailwind classes: the per-asset accordions, the lot inputs, the session history rows, the copy-modal rows. The generated markup is where most of the visible UI lives, so restyling means editing those strings too.
- Some functions overwrite `className` every second or on every toggle (`fetchStatus`, `updateAutoSaveToggleUI`, `switchTab`). Styling you add in the static HTML to those elements will vanish after the first poll unless you also change the class strings in those functions.
- The session log window opened by `viewSession()` loads only `static/styles.css`, so anything it needs must be defined there.

## Approach

Keep Tailwind loaded. Do not try to remove it, because the generated strings and `dark:` variants depend on it. Put the design system in `styles.css` as CSS variables and a small set of semantic component classes (`.card`, `.btn`, `.btn-primary`, `.field`, `.chip`, `.stat`, `.switch`, `.modal`, and so on), then swap the Tailwind utility clutter on each element for those classes. Where a utility is still the simplest tool (flex, grid, gap, spacing), keep using it. Extend the Tailwind config only for fonts and a few colours if that helps.

## Workflow

Work in phases. Run the contract check at the end of every phase and fix anything it reports before moving on.

**Phase 0: baseline.** From the project root:

```
python skills/ui-redesign/check_ui_contract.py snapshot
```

Open the page and note how each state looks today: logged out, logged in with no assets, one asset with two sets, the stopping state, the volume flag, the copy modal steps, the popup. You will compare against this list at the end. If the repo is under git, commit or stash before starting so the diff stays readable.

**Phase 1: foundations.** In `styles.css`, add the colour tokens (light under `:root`, dark under `.dark`), type tokens, radii, shadows, and base styles for body, links, focus rings, scrollbars and `prefers-reduced-motion`. Add the Inter font link and the Tailwind font family in `<head>`. Do not touch the body of the page yet. Check the contract.

**Phase 2: shell.** Header, status badge, theme toggle, Sign Out, mobile tabs, the stat tiles, page background and spacing. Update the class strings inside `fetchStatus()` (the three badge and button states) and `switchTab()` at the same time. Check the contract.

**Phase 3: settings panel.** Asset picker, Copy Lot Setup button, global settings, auto-save switch, the action buttons, the info note, the notice banner, and the live terminal (including the `log()` row markup). Update `updateAutoSaveToggleUI()` classes so the switch looks right on and off. Check the contract.

**Phase 4: per-asset UI.** `renderAssetSettingsPanel()`, `updateLotInputs()`, `renderSetLotGroups()`. Keep every generated id exactly as is, keep each label directly before its input, and keep `border-2 border-red-500` as the class the volume check toggles (give it the new danger look in CSS). Check the contract.

**Phase 5: overlays and history.** Login modal, copy-lots modal (all four states), volume popup, session history rows in `loadHistory()`, the `.session-log` window styles, the loader spinner. Check the contract.

**Phase 6: polish and review.** Walk both themes at 360px, 768px and 1280px widths. Remove leftovers (hard-coded slate and purple colours, tiny text, stray borders). Run the contract check a final time.

## Rules while editing

- Edit class names and structure only. Do not rename functions, change arguments, alter `fetch` or `apiCall` usage, reorder statements in the script, or touch `localStorage` keys (`theme`, `autosave_enabled`, `bot_session_start`).
- If you wrap or move an element, move its id and handlers with it.
- Do not use `<form>` changes that affect submit behaviour: `#view-config` contains the form with `onsubmit="updateConfig(event)"`, and the Terminate, Start and Stop buttons inside it are `type="button"`. Keep them that way so they never submit the form.
- Do not add a build step, npm packages, or new files that the server does not already serve from `static/`. The server only serves `static/`, and the bot runs on a plain Windows VPS.
- Avoid animations on page load. Hover, focus, press, open and close transitions are fine.
- If a design choice would require a behaviour change (for example replacing a native `<select>` with a custom dropdown), do not do it. Style the native control instead.
- Do not fix unrelated bugs you notice. List them in your final report.

## Verification

After each phase run `python skills/ui-redesign/check_ui_contract.py compare`. It must print "UI contract intact". It checks ids and their tag types (including ids built in template strings), inline handlers and which element they sit on, input names, function names, API endpoints and `getElementById` lookups.

The script cannot see classes or runtime behaviour, so also do this by hand at the end, in both themes:

1. Log in, toggle the theme, sign out.
2. On a narrow window, switch all three tabs. On a wide window, confirm all three views show at once.
3. Tick two assets, change Sets to 2, change Max pos on each set, edit lot values, and confirm the inputs rebuild correctly.
4. Type a lot size above the limit for an asset (for example FX Vol 80 with a total over 9) and confirm the red flag and popup appear, then clear when fixed. Dismiss works.
5. Toggle auto-save on and off, change a field, confirm it still saves after about a second. Click Update Configuration.
6. Click Start All, Stop All, and the per-asset Start and Stop buttons, and confirm the status badge and button states cycle correctly through Offline, Active and Stopping. Test Terminate All only on a demo account.
7. Open Copy Lot Setup, go through source, targets, the differing-sets prompt (with all three options), and the success state.
8. Load Session History, View a log (opens in a new window, themed correctly), and Download one.
